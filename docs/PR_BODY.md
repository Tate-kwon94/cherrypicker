# 검수 가격 기반 비교로 전환 (감사 대응 1차)

73개 항목 감사에 대한 구현입니다. 합의된 범위 그대로 — **별도 브랜치·구현·테스트·측정·문서·리뷰 가능한 PR**까지이고, **머지·배포·플래그 활성화·단계 0 완료 표시는 하지 않았습니다.** 다섯 개 기능 플래그는 전부 꺼진 채입니다.

## 이 브랜치가 지키려는 것

> **공개 결론 — 헤드라인 판정, 절약액, 판매처 수, 서버 렌더 HTML — 은 운영자가 검수한 가격으로만 만든다.**
> 사용자가 캡처하거나 직접 입력한 가격은 현재 세션 안에서만 쓰이고 공개 결론의 근거가 되지 않는다.

감사의 가장 무거운 지적(H-02)이 이것이었고, 나머지 상당수가 같은 문장의 다른 얼굴이었습니다. 아래 변경은 대부분 "이 문장이 코드에서 참이 되게 만드는 일"입니다.

## 반복해서 나온 결함 한 가지

작업 중 같은 형태를 **여섯 번** 만났습니다. **방어 코드는 있는데 실행되지 않거나, 실행되어도 일부만 덮는 것.**

| 방어 | 왜 작동하지 않았나 |
| --- | --- |
| 신선도 14일 상한 | 범용 검사가 먼저 1일로 던져 **한 번도 실행된 적 없음**. 그런데 UI가 그 죽은 표를 읽어 사용자에게 "최대 14일"이라고 표시 |
| `currency-mismatch` | `toContractOffer`가 모든 검수 가격을 `"KRW"`로 단정 — 입력이 상수라 분기가 죽음 |
| `variant-mismatch` | `variantKey`에 상품 id가 들어가고 양쪽이 같은 id로 필터링돼 두 값이 절대 다르지 않음 |
| OCR 다상품 거부 | **카탈로그에 있는** 상품이 둘일 때만 발동. 추천 상품 띠의 외부 상품은 그대로 통과 |
| `(captured \|\| verified)` 가드 | 예시 fixture를 거르던 조건인데 fixture가 사라져 항상 참 |
| CSP `script-src` | `'unsafe-inline'`이 있어 모든 인라인 스크립트가 허용됨 — 지시문이 문서였지 통제가 아니었음 |

타입 검사도 테스트도 통과하고 화면도 정상이라, 이 종류는 **읽어서 찾는 수밖에 없었습니다.**

## 주요 변경

### 신뢰 경계

- 공개 비교는 검수 가격 쌍에서만 생성. 배열 순서 폴백(`offers[0]`/`offers[1]`)을 제거해 캡처한 국내가가 면세 자리에 들어갈 수 없음
- 계약 실패는 `0원 절감`이 아니라 **비교 없음(`null`)**. 검수 가격이 하나도 없으면 렌더된 HTML에 **원 금액이 하나도 없음**(테스트로 고정)
- 사용자 입력에 별도 비교면(`내 입력 포함 비교`) 부여. `PersonalComparison`은 `VerifiedComparison`에 대입되지 않고, 승패 필드가 없으며, 금액은 감싼 타입이라 `verdictFor`·금액 포맷터가 받지 못함 — 오용 네 가지를 `@ts-expect-error`로 고정
- 캡처가 검수 결론에 반영됐다고 말하던 문구 두 곳 제거. 캡처 하나가 "면세 3곳·국내 4곳" 표기를 지우던 문제 포함

### 가격 데이터

- 신선도 정책을 단일 모듈로 통합(`1/3/7일`), 죽은 14일 분기 제거, UI 문구 정정
- `price_offers.currency` 컬럼 추가 + 마이그레이션. 계약의 통화 검사가 실제 값을 읽음. 표시도 통화를 따름
- 상품 upsert를 insert-only로 바꾸고 충돌 거부. 승인 이력 보존. 불량 행 하나가 피드 전체를 503으로 만들던 문제 격리
- 검수 대상을 **본품으로 한정**(세트·증정·한정판·묶음 거부)

### OCR

- 줄 단위 파싱으로 전환. 상품이 둘 이상이면 상품·금액을 모두 비우고 후보 목록으로 선택 요구
- 금액·용량 검색을 **상품 줄 기준**으로 제한 — 장바구니 아래 추천 상품 띠가 가격을 가로채던 문제
- 판매처를 패턴 배열 순서가 아니라 상품 근접도로 선택
- 필드별 provenance를 읽은 값에서 유도 — 기본 용량을 채우고 "인식 완료"라고 표시하던 문제

### 저장소

- `내 비교함` schema v2. `SavedPickBasis`에 `"captured"` 멤버가 없어 캡처 근거 pick이 **표현 불가능**
- `savedAt`을 숫자와 해석으로 분리(`device-clock`/`legacy-import`/`unknown`). `event.timeStamp`가 epoch로 위장하던 문제
- 미래 schemaVersion 행은 파괴하지 않고 건너뛰며, 그 경우 **저장도 거부** — 읽기만 막으면 목록이 비어 보이고 저장 버튼이 열려 클릭 한 번에 사라짐

### 보안·배포

- 카카오 임포트 비밀값을 셋으로 분리(전부 있고 서로 달라야 함), HTTPS 전용, 헤더 전용 인증, TTL 2분, 전달 후 소비
- 모든 Worker 응답에 공통 보안 헤더. CSP는 **요청마다 새 nonce**를 발급해 `script-src`에서 `'unsafe-inline'` 제거
- Tesseract worker·wasm 자체 호스팅 — 제3자 출처가 우리 페이지에서 코드를 실행하지 않음
- 기능 플래그를 요청 시점 서버 판독으로 이동(`NEXT_PUBLIC_*`는 빌드에 고정되어 끌 수단이 못 됨). 정확히 `"true"`만 켬
- **플래그가 실제로 무언가를 막는지 검사.** 넷은 이름만 있고 아무 코드도 읽지 않았고, 하나(`TELEMETRY_ENABLED`)는 끌 대상 자체가 없어 제거
- canonical URL을 요청 호스트가 아닌 설정에서 생성

### 검증 장치

- `build/check-config-drift.mjs` — 배포 설정 3자 대조 (빌드 전/후)
- `build/check-schema-drift.mjs` — Drizzle 스키마 ↔ 마이그레이션 ↔ 손으로 쓴 SQL 대조. **거짓 통과 다섯 방향을 재현해 검증함**
- `.github/workflows/verify.yml` — 모든 푸시·PR에서 `npm run verify` + 배포 의존성 취약점 검사

## 의도적으로 닫아 둔 것

코드만 보면 "아직 안 한 것"과 구분되지 않아 [`docs/PRICE_DATA_CONTRACT.md`](PRICE_DATA_CONTRACT.md)에 여는 조건과 함께 적었습니다.

| 항목 | 이유 | 여는 조건 |
| --- | --- | --- |
| USD 가격 등록 | 금액 컬럼이 정수라 `$89.50`을 담을 수 없음. 89로 절사하면 더 조용한 오류 | 금액을 최소 단위로 저장하는 마이그레이션 |
| 캡처 가격 저장 | 재검증 방법이 없고, 프라이버시 표면 대비 Phase 0에서 얻는 가치가 없음 | 보존 기간·재검증 방법·고지 방식 확정 |
| 변형(`variantId`) | 카탈로그가 본품과 세트를 구분하지 않음 | 카탈로그를 변형 기준으로 재작성 |
| OCR 언어 데이터 | 코드가 아니라 데이터이고, 공개 결론에 닿지 않음 | 필요 시 R2 등으로 이전 |

## 검증


`lint → typecheck → check:types → check:config → check:schema → test → check:config:post`.
현재 **테스트 163개**(main 기준 테스트 파일 8개 → 23개), lint 경고 0, `tsc` 오류 0.

## 리뷰어가 직접 봐야 할 것

자동 검증으로 덮이지 않는 부분입니다.

1. **CSP 리포트** — 정책은 여전히 `Report-Only`입니다. 실제 배포에서 무엇이 걸리는지 관측한 뒤에만 enforce로 올려야 합니다.
2. **실제 콜드스타트 배포** — D1 바인딩과 설정 3자 대조는 빌드 산출물까지만 확인합니다.
3. **카카오 인앱 브라우저 실측** — fragment 전달과 `Sec-Fetch-*` 헤더가 실제로 어떻게 오는지는 측정하지 못했습니다.
4. **OpenAI Sites 엣지 헤더 규약**(`AUTH-01`) — 관리자 인증이 무엇을 신뢰해도 되는지는 저장소 밖의 사실입니다.
5. **법무 승인**(`LEGAL-01`) — 가격 비교 표기와 주류 관련 문구.
6. **본품 판별 오탐** — 상품명으로 세트를 거르므로, 운영 중 잘못 막히는 이름이 있는지 봐야 합니다. 현재 파일럿 15개는 전부 통과합니다.
